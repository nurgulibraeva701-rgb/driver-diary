# Дневник смен водителя

Сервер на Python 3.8+ (только стандартная библиотека) + веб-клиент (один HTML-файл). Ничего устанавливать не нужно.

## Запуск
```
python -m app.server        # http://localhost:8000  (другой порт: python -m app.server 9000)
python -m unittest -v       # тесты
```
Данные лежат в `data/trips.json`. Новые поездки дописываются в этот же файл.

## API
| Метод | Путь | Что делает |
|---|---|---|
| GET | `/api/days` | даты, в которые есть поездки |
| GET | `/api/trips?date=YYYY-MM-DD` | поездки за день + сводка |
| GET | `/api/summary?date=YYYY-MM-DD` | только сводка |
| POST | `/api/trips` | добавить поездку |

Сводка: `trips`, `revenue` (выручка), `commission`, `net` (на руки = выручка − комиссия), `cash` и `card` (`trips`, `amount`).

## Решения
- **День поездки** — дата начала в часовом поясе самой поездки (из её `start`).
- **Проверки при добавлении**: `id` обязателен, `amount > 0`, `end > start`, у времени есть часовой пояс, `payment` ∈ {cash, card}, `0 ≤ commission ≤ amount`. Ошибка → `422`.
- **Защита от дублей** по `id`: повтор идентичной поездки → `200` и `created: false`, дубль не создаётся; тот же `id` с другими данными → `409`. Клиент генерирует `id` один раз на форму, поэтому двойной клик тоже не создаёт дубль.
- Запись в файл атомарная (temp + replace) и под блокировкой.

## Тесты (`tests/test_app.py`)
Расчёт сводки (пусто, суммы, разбивка, округление), валидация, дубли (повтор, конфликт, перезапуск сервера), сквозной HTTP-сценарий.

## Как использован ИИ

Дизайн приложения я сделала сама в Figma (экраны «Моя смена», «Данные смены», «История смен», «Подробности смены»). Макет я отправила Claude, и он сделал первоначальную версию: сервер на Python с API, клиент в стиле макета и тесты. После этого я сама запускала приложение, проверяла его в браузере и исправляла детали и ошибки.

**Где ИИ ошибся и что исправили:**
- В макете были смены с пробегом и расходами, а в задании данные о поездках. Claude адаптировал экраны под поездки: «Доход» стал выручкой, «Расходы» стали комиссией, «Чистый доход» стал суммой «на руки».
- В истории не было видно время работы. Я заметила это и добавила диапазон времени для каждого дня, например `08:10–12:15`.
- На экране появлялось «NaN ч NaN мин». Причина: браузер Safari не разбирал некоторые форматы времени, которые принимал сервер. Теперь сервер приводит время к стандартному виду, а клиент устойчив к таким форматам. Для этого добавлен тест.
- Один тест был написан неверно: ожидался ответ 409, а сервер правильно вернул 422, потому что комиссия превышала сумму. Тест исправлен.
- Тесты изначально не находились командой `python -m unittest`, пока не добавили `tests/__init__.py`.
